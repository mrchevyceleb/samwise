# AutoSam Claude account

This Moria deployment pins `/home/mrchevyceleb/.claude-tardis` for every Claude coder and reviewer, and for the worker's shell descendants. It checks an authenticated first-party subscription and the approved account/organization fingerprint before each launch. Missing, symlinked, unauthenticated or wrong-account profiles refuse launch. API keys, alternate OAuth tokens and provider overrides are removed from child environments; Claude settings sources are disabled so project settings cannot redirect billing. Personal credentials are never read or copied. CLI version detection remains a non-billable installation check.

Build with `npx tauri build --no-bundle`. Before activation, the queue owner must confirm no task is mid-run. Stop `samwise-agent-one.service`, install the built binary and `ops/systemd/team-claude.conf` under `~/.config/systemd/user/samwise-agent-one.service.d/`, then run `systemctl --user daemon-reload`. Run the installed binary with `--check-claude-account` before starting the service. Run this check while the service is stopped. It performs no task or database work, although the Claude CLI may refresh its team subscription token. Verify the running parent's profile and a real Claude launch, reporting only fingerprints and names.

If authentication fails, leave the service stopped. The drop-in sets `RestartPreventExitStatus=78` so an intentional authentication refusal cannot enter a restart loop. Never restart the old credential-copying binary: it could overwrite the team profile with personal credentials. An auth failure during coding leaves its task queued and on hold, preserving output and its worktree. Restore the team login, verify the check, then release the task hold. No personal login edits or account rotation are part of this fix.
