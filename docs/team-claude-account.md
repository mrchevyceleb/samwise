# AutoSam Claude account

This Moria deployment pins `/home/mrchevyceleb/.claude-tardis` for every Claude coder and reviewer, and for the worker's shell descendants. Install `ops/bin/claude` as the executable `/home/mrchevyceleb/.local/lib/autosam/bin/claude`; the worker puts this directory first on PATH and refuses normal startup if that launcher is missing or changed. Shell Claude runs enter the same native account guard, including the settings restriction. It checks an authenticated first-party subscription and the approved account/organization fingerprint before each launch. Missing, symlinked, unauthenticated or wrong-account profiles refuse launch. API keys, alternate OAuth tokens and provider overrides are removed from child environments. Native user, project and local settings sources stay enabled so Matt's global rules, repo `CLAUDE.md` and local instructions load. Command-line settings pin the profile and first-party login and clear conflicting credentials, helpers and provider switches from all three sources. The same policy guards the auth probe and every native or shell launch. Personal credentials are never read or copied. CLI version detection remains a non-billable installation check.

The user source reads Matt's global rules at `/home/mrchevyceleb/.claude-tardis/CLAUDE.md` (currently a managed symlink). It does not select the personal profile. Native hooks remain enabled, including the team profile's secret-print guard; a repo cannot turn those guards off with `disableAllHooks`. The CLI policy disables project MCP auto-enablement and credential helper commands, and clears proxy/TLS/client-certificate overrides while requiring TLS verification. `SSL_CERT_FILE` and `SSL_CERT_DIR` use Moria's normal OpenSSL defaults (`/usr/lib/ssl/cert.pem` and `/usr/lib/ssl/certs`), so Bash children retain the system trust store. Empty certificate paths break Python/OpenSSL and must never be used here. The worker's inherited `NODE_OPTIONS` is preserved and takes precedence over file settings, retaining its build memory allowance without accepting a repo-supplied preload. Repo instructions still load natively. The independent diff reviewer retains its pre-existing explicit `--safe-mode`; this account change does not remove that deliberate review isolation.

Build with `npx tauri build --no-bundle`. Before activation, the queue owner must confirm no task is mid-run. Stop `samwise-agent-one.service`, install the built binary and `ops/systemd/team-claude.conf` under `~/.config/systemd/user/samwise-agent-one.service.d/`, then run `systemctl --user daemon-reload`. Run the installed binary with `--check-claude-account` before starting the service. Run this check while the service is stopped. It performs no task or database work, although the Claude CLI may refresh its team subscription token. Verify the running parent's profile and a real Claude launch, reporting only fingerprints and names.

If authentication fails, leave the service stopped. The drop-in sets `RestartPreventExitStatus=78` so an intentional authentication refusal cannot enter a restart loop. Never restart the old credential-copying binary: it could overwrite the team profile with personal credentials. An auth failure in coding, a secondary summary/review/repair call, or a direct pi Anthropic login holds the owning task and preserves output and its worktree. Secondary callers cannot swallow that hold. Pi with the Anthropic provider refuses; use the guarded Claude coder for subscription work. Health reports distinguish an installed CLI from a verified team login. Restore the team login, verify the check, then release the task hold. No personal login edits or account rotation are part of this fix.

The fixed profile and approved account fingerprint are deliberate: a different login must not silently become billable. Changing that binding requires an approved source update. Account availability never selects another profile. No live worker proof is claimed until Sam runs a real review after Max approves activation.
